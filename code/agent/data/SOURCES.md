Changes and choices ([v2.5.9z19], for the converters' round-trip tests in `test_tool_convert.py`):

- `toolrl_rows.jsonl`: the parquet rows as JSON lines in verl's shape (`data_source`, `prompt`, `ability`, `reward_model`),
  with `extra_info` cut to `index` and `split` (the full rows repeat the instruction, input and output there). The rows
  were picked to cover a single call, three parallel calls, a multi-turn query with `<obs>`, an integer argument of a tool
  with an obfuscated name, a text-only answer and a broken reference (`convert_toolrl.py` skips the last two); rows that
  match the runbook's leak-scan pattern were not eligible.
- `claweval/`: unmodified task files, in the dataset's own layout. calendar-001 (an action check, a forbidden tool, answer
  checks dropped), notes-002 (an audit sequence and an equals check), notes-028 (two contains checks on a list argument),
  todo-011 (an audited argument the service model lacks), todo-022 (two equals values on one argument: two calls),
  inventory-007 and web_real-004 (tool parameters given in the YAML, two shapes), OCR-066 (no tools: skipped). None of
  them is among the files whose key-shaped strings opd-lab-assets replaced (its `REPLACED.md`).
- `clawenvkit_schemas.json`: written by `python convert_claweval.py --extract-schemas <ClawEnvKit checkout> --commit <sha>`,
  which reads the service files with Python's `ast` (nothing in them is run): each `@app.post` / `@app.get` route's
  request model as a JSON schema (field types, required fields, literal defaults, `Field` descriptions); the harness's
  audit, reset and health routes left out.
